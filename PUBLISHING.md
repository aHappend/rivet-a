# Publication policy

1. Read each generation's native engineering state without modifying the active project.
2. Publish status while work is in progress; export source only after native engineering acceptance.
3. Export selected rtl/design/tests files, unchanged product READMEs and predecessor reference RTL, approved PDF/LaTeX, public documentation and brand assets. Keep generated status prose separate from product READMEs.
4. Reject symlinks, private machine paths and credential-like text. Do not export internal state or sessions.
5. Fetch main and fast-forward only; commit changed product files with co-author attribution.
6. Push normally and verify the remote commit. A rejected push remains an explicit failure, not success.
7. Retry publication on the next scheduled cycle without restarting engineering. No change means no new commit.

The private publisher observes generations independently. A publication error does not change engineering acceptance.
